# مركز النخبة

واجهة عربية RTL لاختيار الصفوف والمواد، مع الأسعار وأسماء المدرسين. تتضمن لوحة إدارة ويب على `/admin` لإدارة الكتالوج والطلبات والاشتراكات والإعلانات والموجز والعلامات.

## التثبيت والتشغيل

```sh
npm install
npm run server
```

يتطلب الخادم Node.js 22.13 أو أحدث. يستخدم SQLite عبر `better-sqlite3` ولا يحتاج إلى حساب مزوّد أو بيانات اتصال خارجية.

في طرفية ثانية:

```sh
npm run dev
```

افتح عنوان Vite الذي يظهر في الطرفية. مع إعدادات `.env.example` يعمل API محلياً على `http://127.0.0.1:3001`؛ يقرأ المنفذ من `API_PORT` أو `PORT` والعنوان من `API_HOST`. يمرر Vite طلبات `/api` إلى المنفذ نفسه. للوصول من الهاتف على الشبكة نفسها استخدم `npm run dev -- --host 0.0.0.0`.

## النشر على Render

ملف `render.yaml` يجهز خدمة Node.js باسم `elite-center-api`، يبني واجهة React ويقدمها مع الـAPI من النطاق نفسه، مع فحص صحة على `/api/health` وقرص دائم بسعة 1 GB على `/var/data`. أنشئ Blueprint جديداً في Render واربطه بمستودع المشروع، ثم أدخل المتغير المطلوب عند الطلب:

- `ADMIN_ACCESS_CODE`: رمز دخول لوحة الإدارة. محلياً القيمة المطلوبة هي `isam000` في `.env`؛ استخدم قيمة قوية وفريدة عند النشر.

الخدمة تستمع على منفذ Render وعلى `0.0.0.0`. افتح `https://<اسم-الخدمة>.onrender.com/admin` للوحة الإدارة، أو النطاق نفسه للواجهة العامة؛ لا تحتاج إلى نشر موقع منفصل أو ضبط `VITE_API_BASE_URL` لأن الواجهة والـAPI من الأصل نفسه. قاعدة البيانات هي SQLite مجانية ومضمنة مع Node.js، ويحفظ الخادم بياناته في `elite-center.sqlite` داخل `ELITE_DATA_DIR` (على Render: `/var/data`). عند أول تشغيل تُهاجر ملفات JSON الموجودة تلقائياً إلى SQLite؛ بعدها تكون قاعدة SQLite هي المصدر المعتمد، وتبقى ملفات JSON القديمة كنسخة ترحيل غير محدثة. صور الملفات الشخصية تبقى ملفات منفصلة في مجلد البيانات. يتطلب القرص الدائم في إعداد Render الحالي خطة مدفوعة؛ لا تحذف القرص ولا تنشئ قرصاً جديداً عند إعادة النشر. أبقِ الخدمة على نسخة واحدة؛ لا تستخدم ملف SQLite مشتركاً بين عدة خوادم أو أقراص.

إذا استضفت واجهة الويب على نطاق منفصل، اضبط `VITE_API_BASE_URL` وقت البناء ليشير إلى خدمة الـAPI، وأضف أصل الواجهة إلى `CORS_ORIGINS` في Render. تطبيق Flutter الأصلي يتصل بالـAPI مباشرة عبر HTTPS.

بيانات المشروع المحلية الحساسة مستثناة من Git، لذلك لا تنتقل تلقائياً إلى Render. إذا كانت لديك طلبات أو اشتراكات قائمة، صدّر نسخة احتياطية وانقل ملفات JSON المطلوبة إلى القرص الدائم بأداة نقل آمنة قبل اعتماد الخدمة للطلاب؛ لا ترفعها إلى المستودع أو إلى محادثة عامة. تحقق بعد النشر من `/api/health` ثم `/api/catalog`، وافتح `/admin` واختبر تسجيل الدخول قبل تحويل المستخدمين.

## النشر على Firebase Hosting

يستضيف Firebase نسخة الويب المبنية بواسطة Vite من `dist/`، بينما يبقى الـAPI على Render. أضف نطاق Firebase Hosting إلى `CORS_ORIGINS` في إعدادات API على Render، ثم ابنِ الواجهة بعنوان API المنشور وانشرها:

```sh
VITE_API_BASE_URL=https://elite-center-server.onrender.com npm run build
firebase deploy --only hosting
```

يعيد `firebase.json` توجيه مسارات الواجهة إلى `index.html` لدعم التنقل داخل التطبيق. أعد البناء بعد أي تغيير للواجهة؛ مجلد `dist/` مخرجات مولّدة ومستثناة من Git.

## لوحة الإدارة

انسخ `.env.example` إلى `.env` واضبط `ADMIN_ACCESS_CODE=isam000` محلياً. شغّل `npm run server` و`npm run dev`، ثم افتح `/admin`. الجلسة الإدارية محفوظة في Cookie من نوع `HttpOnly` وتُلغى عند تسجيل الخروج أو إعادة تشغيل API. احمِ الموقع عبر HTTPS عند النشر، وغيّر الرمز المحلي الافتراضي إلى قيمة خاصة بك قبل إتاحته على الإنترنت. رمز ثابت وقصير غير مناسب لتأمين نظام منشور.

تدير اللوحة الصفوف والمواد والأسعار والمدرسين، الأخبار العامة، طلبات التسجيل، أكواد الاشتراك، إعلانات الإدارة، بلاغات ومنشورات الموجز، وإدخال العلامات مباشرةً. يظهر كود الطالب مرة واحدة عند الموافقة أو الإنشاء أو إعادة الإصدار؛ خزّنه بأمان وشاركه يدوياً مع الطالب. لا يرسل النظام رسائل تيليغرام.

## البيانات والوسائط

تُخزن بيانات الكتالوج وطلبات التسجيل والاشتراكات والجلسات والتفاعلات والملفات الشخصية والعلامات والإعلانات في قاعدة SQLite. ملف قاعدة البيانات وملفات SQLite المؤقتة مستثناة من Git. عند الترقية من النسخة السابقة، يستورد الخادم ملفات JSON إلى SQLite مرة واحدة لكل سجل إذا لم يكن موجوداً فيها؛ احتفظ بنسخة احتياطية آمنة من مجلد البيانات قبل الترقية، ولا تعدّل ملفات JSON بعد الترحيل لأنها لم تعد المصدر المعتمد. يبقى ملف الدورات الرقمية القديم وحقله في الكتالوج محفوظين كبيانات تاريخية، لكنهما لم يعودا يظهران في الواجهة أو API؛ لا تحذفهما يدوياً دون مراجعة/ترحيل مستقل.

يُرسل الطالب طلباً يتضمن اسمه وهاتفه وبريده وصفه والمواد الدراسية المختارة. عند الموافقة من اللوحة ينشئ الخادم كوداً عشوائياً مرتبطاً بالبريد ويحفظ تجزئته فقط في ملف الاشتراكات، ويعرض الكود الجديد مرة واحدة للمراجع ليشاركه يدوياً مع الطالب. يسجل الطالب الدخول بالبريد والكود، وتستمر جلسة الوصول ست ساعات.

جلسات المتصفح تستخدم Cookie من نوع `HttpOnly` و`SameSite=Lax`؛ تُحفظ معرّفات الجلسات المجزأة في SQLite ولا يحفظ الخادم رمز الجلسة الصريح. يجب حماية مجلد قاعدة البيانات ونسخه احتياطياً. عند تشغيل الخادم خلف reverse proxy HTTPS مضبوط وموثوق فقط، اضبط `TRUST_PROXY=true` حتى يضيف الخادم وسم `Secure` إلى Cookie. تطبيق Flutter يستخدم Bearer token محفوظاً في التخزين الآمن للنظام، وتسجيل الخروج يبطل الرمز من الخادم.

يستخدم Flutter حزمة `flutter_secure_storage` لحفظ جلسة الطالب في التخزين الآمن للنظام، ولا يحفظ رمز الجلسة في `localStorage`.

تُحفظ بيانات موجز الطلاب والتعليقات والتفاعلات والمحفوظات والبلاغات وإعلانات الإدارة والإشعارات والعلامات وسجل الاستيراد في قاعدة SQLite بمعاملات، مع تفعيل WAL لضمان سلامة الكتابات المتزامنة. شغّل نسخة واحدة فقط من الخادم على ملف قاعدة البيانات؛ SQLite على قرص محلي لا يصلح قاعدة مشتركة لعدة نسخ.

### موجز الطلاب وإعلانات الإدارة

الموجز خاص بالجلسات النشطة، والنشر النصي محدود بـ2000 حرف. يمكن للطلاب التعليق والتفاعل والحفظ والإبلاغ؛ البلاغ الواحد لكل طالب/منشور لا يتكرر. يراجع المدير البلاغ من قسم الإشراف في لوحة الإدارة، ويعاين المنشور قبل إخفائه أو إغلاق البلاغ. الأخبار المنشورة على الموقع تبقى عامة، أما إعلانات الإدارة فتُنشر من اللوحة بعد التأكيد وتظهر في مساحة الطالب منفصلة مع حالة مقروء/غير مقروء؛ يمكن أرشفتها من إدارة الإعلانات. جميع عمليات حفظ المجتمع والنتائج تستخدم كتابة ملف ذرياً ونسخة `.bak`.

### إدخال العلامات

من قسم «إدخال العلامات» اختر الصف ثم المادة؛ تعرض اللوحة تلقائياً الاشتراكات النشطة المسجلة في هذه المادة. أدخل اسم الاختبار والفصل والعلامة العظمى والتاريخ، ثم سجّل علامة كل طالب في صفه. يمكن ترك خانة فارغة لتجاوز طالب في هذه الدفعة، والضغط على Enter ينقلك إلى خانة الطالب التالي. تتوفر إحصاءات مباشرة وبحث وتصفية بحسب الطلاب الذين أُدخلت علاماتهم أو لم تُدخل بعد. قبل النشر تعرض اللوحة عدد النتائج الجديدة والنتائج التي ستُحدّث. يتحقق الخادم من الصف والمادة واشتراك كل طالب ومن أن العلامة ضمن الحد الأعلى قبل الحفظ. تظهر العلامات للطلاب المعنيين فقط ويصلهم إشعار بالنشر. إذا أُدخلت علامة للطالب نفسه والمادة والاختبار والفصل نفسيهما، تُحدّث النتيجة بدلاً من إنشاء سجل مكرر.

## تطبيق الهاتف (Flutter)

مصدر تطبيق الطلاب الأصلي موجود في `flutter_app/`. يشارك الـAPI وبيانات الكتالوج مع الموقع، ويشمل الصفحة الرئيسية والصفوف والمواد والمدرسين، طلب التسجيل، تسجيل الدخول، ملف الطالب، العلامات، الإعلانات، الطلبات، وموجز الطلاب. تبقى لوحة الإدارة والواجهة العامة على الويب في المشروع الحالي.

يتطلب Flutter stable وAndroid SDK Platforms 34 و36 وJDK 21. يستخدم التطبيق شعار المركز لشاشة البداية وأيقونة Android، ويعرض اسم التطبيق بالإنجليزية أو العربية بحسب لغة الجهاز. من جذر المشروع:

```sh
cd flutter_app
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3001
```

العنوان أعلاه مخصص لمحاكي Android عند تشغيل API محلياً. على جهاز فعلي استخدم عنوان الجهاز الذي يشغّل API واجعل `API_HOST=0.0.0.0`، أو استخدم عنوان API منشوراً عبر HTTPS. يستخدم التطبيق افتراضياً خدمة `https://elite-center-server.onrender.com`؛ تحقق من `/api/health` و`/api/catalog`، أو مرّر العنوان الفعلي عبر `API_BASE_URL` عند تغيّره. تنتهي طلبات API بمهلة 12 ثانية وتعرض الواجهة خيار إعادة المحاولة عند فشل الاتصال.

يحفظ التطبيق بيانات الكتالوج والأخبار العامة محلياً؛ يعرض النسخة المحفوظة فوراً لمدة 10 دقائق، ويستخدمها عند تعذر الخادم حتى عمر 30 يوماً. السحب للتحديث يتجاوز الذاكرة المؤقتة ويطلب أحدث نسخة. لا تُخزَّن جلسات الدخول أو بيانات الطالب الخاصة ضمن هذه الذاكرة.

### تجهيز Firebase Cloud Messaging

توجد حزم Firebase Core وCloud Messaging ومعالجة الرسائل أثناء فتح التطبيق أو عمله بالخلفية، ويُسجّل الجهاز في Firebase Messaging ويُحفظ معرّف تثبيت Firebase (FID) في التخزين الآمن باستخدام واجهات Firebase الحديثة. يمكن بناء التطبيق وتشغيله قبل إضافة إعدادات Firebase؛ سيستمر طلب إذن Android بالطريقة الحالية، لكن لن يتم تسجيل الجهاز في FCM حتى تضاف القيم الصحيحة.

1. أنشئ مشروعاً في Firebase Console وأضف تطبيق Android بمعرّف الحزمة `com.elitecenter.elite_center`.
2. نزّل `google-services.json` من صفحة إعداد التطبيق، ثم انسخ القيم التالية إلى `firebase-options.json` محلياً باستخدام المثال [firebase-options.example.json](./flutter_app/firebase-options.example.json):
   - `FIREBASE_API_KEY`: قيمة `current_key` من `api_key`.
   - `FIREBASE_APP_ID`: قيمة `mobilesdk_app_id` من العميل الذي يحمل الحزمة `com.elitecenter.elite_center`.
   - `FIREBASE_MESSAGING_SENDER_ID`: قيمة `project_number` من `project_info`.
   - `FIREBASE_PROJECT_ID`: قيمة `project_id` من `project_info`.
3. من مجلد `flutter_app` شغّل:

   ```sh
   flutter run --dart-define-from-file=firebase-options.json
   ```

   أو لبناء APK:

   ```sh
   flutter build apk --release --dart-define-from-file=firebase-options.json
   ```

   الملف المحلي مستثنى من Git. القيم هي إعدادات عميل Firebase وليست مفتاح خدمة إدارية؛ لا تضع بيانات Service Account أو مفاتيح Admin SDK في التطبيق.

4. فعّل Firebase Cloud Messaging للمشروع واختبر إرسال رسالة إلى التطبيق بعد فتحه مرة واحدة والموافقة على الإشعارات. الرسائل أثناء فتح التطبيق تظهر داخل التطبيق، ورسائل FCM التي تحتوي notification تظهر من Android بالخلفية. للحصول على إرسال تلقائي من لوحة الإدارة أو الخادم، يلزم لاحقاً تسجيل الجهاز لدى API وإعداد Firebase Admin SDK ببيانات اعتماد سرية في متغيرات بيئة Render؛ لا يرسل الخادم الحالي إشعارات FCM بعد.

يطلب التطبيق إذن إشعارات Android مرة واحدة بعد ظهور الصفحة الرئيسية. لبناء APK تجريبي من جذر المشروع:

```sh
npm run android:build
```

ينتج الملف في `flutter_app/build/app/outputs/flutter-apk/app-debug.apk`. لا تستخدم عنوان HTTP غير مشفر خارج شبكة التطوير المحلية.

## حدود النسخة الحالية

التسجيل يرسل طلباً للمراجعة؛ الكود يثبت صلاحية الاشتراك لكنه ليس نظام استعادة كلمة مرور أو هوية دائمة. قاعدة SQLite مناسبة لخادم واحد وقرص دائم، لكنها ليست قاعدة مُدارة متعددة المناطق أو مخزناً متعدد النسخ. قاعدة SQLite نفسها مجانية، لكن خطة Render التي توفر القرص الدائم في الإعداد الحالي مدفوعة؛ استضافة مجانية بلا قرص دائم قد تفقد البيانات عند إعادة تشغيل الخدمة. لا يوجد دفع إلكتروني. توقيع إصدار Android للنشر وإعداد خدمة push الخلفية غير مكتملين.

## الفحوصات

```sh
npm run build
npm run lint
npm test
```

تعمل اختبارات API على مجلد بيانات مؤقت ومعزول، ولا تستخدم بيانات الطلاب المحلية أو ملف `.env`.

بيانات الصفوف والأسعار الحالية ابتدائية ويمكن تعديلها من لوحة الإدارة. يدعم التخزين الحالي مثيلاً واحداً للخادم وملفات بيانات محلية؛ انقل البيانات إلى مخزن مشترك قبل التوسع إلى عدة نسخ.
